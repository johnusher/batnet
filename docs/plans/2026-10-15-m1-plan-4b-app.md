# Milestone 1, plan 4b: the full app, and the real app in the simulator's phone

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app people will use - with an outbox for messages written out of range, bedside mode, notification and speaker settings, German, help and an admin Alert box - and the very same app running in the online simulator's phone against batnet's real code for every simulated house.

**Architecture:** Server side, posts carry a client-chosen `clientId` so a retried send is stored once; `account.update` carries notification settings into the log, where the house Pi (plan 5) will read them. App side, an IndexedDB outbox retries on reconnect; Screen Wake Lock gives bedside mode; a string table gives English and German. Simulator side, every simulated house runs a real `web.Server` whose people are seeded as approved accounts; the WebAssembly bridge exposes in-process HTTP and an event queue per session; the phone panel loads the real app files with a shim that routes `fetch` and `EventSource` into the engine.

**Tech Stack:** Go 1.26 (`net/http/httptest` for in-process requests), plain JavaScript (IndexedDB, Wake Lock), WebAssembly bridge from plan 2.

**Spec:** [`docs/specs/2026-10-15-m1-design.md`](../specs/2026-10-15-m1-design.md) §8 (outbox, alerts in the open app, bedside), §9a (speaker settings), §14a (the real code in the simulator); decisions 0018, 0019.

**Milestone 1 plans:** 1, 2, 3, 4a done · **4b the full app (this)** · 3b real radios · 5 Pi set-up · 6 image and installer.

## Global Constraints

- `clientId`: 8-64 characters of `[A-Za-z0-9_-]`; one stored message per (account, clientId); a repeat returns the stored message with 200.
- Settings in `account.update`: `speaker` (bool, default off), `quietHours` (bool, default on). Only the account's own sessions change them.
- Strings: every user-visible string in the app comes from the `T` table with `en` and `de`; the language follows `navigator.language` unless chosen in Settings (kept in `localStorage`, wrapped in try/catch).
- The outbox lives in IndexedDB (`batnet` database, `outbox` store); it survives a reload; items are sent oldest first; an item is removed only after a 200 (or a 4xx other than 401/429, shown as failed).
- Bedside mode uses `navigator.wakeLock.request('screen')` when available and says so when not.
- The simulator: seeded accounts use one shared placeholder PIN (`000000`), hashed once; seeding writes entries straight into every node's store (an established village), not over the air.
- Determinism stays (same seed, same run) with servers in the village.

## Review Focus

1. **A retried post** (the response was lost, the outbox sends again): stored once. → Task 1 `TestClientIDDedup`.
2. **Settings changed for someone else** (another account's id in the body): refused. → Task 2 `TestSettingsOwnOnly`.
3. **The simulator's phone signs in as a seeded person, posts, and the post reaches other houses' people through the real sync**, in virtual time. → Task 4 `TestSimPhonePostTravels`.
4. **Events in the simulator**: a session sees only what it may see, and a drained queue does not repeat. → Task 5 `TestSimEvents`.
5. **Seeding breaks determinism or floods the air.** → Task 4 `TestSeededDeterministic`, scenarios unchanged.

// FindClient returns account's message with this clientId, or nil.
func (s *State) FindClient(account, clientID string) *Message {
	s.mu.RLock()
	defer s.mu.RUnlock()
	for i := len(s.messages) - 1; i >= 0; i-- {
		if m := s.messages[i]; m.From == account && m.ClientID == clientID {
			return m
		}
	}
	return nil
}
